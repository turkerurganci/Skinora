## 1. Neden bu tur yapıldı

E2E ağı (10 süit) Steam OAuth'u JWT enjeksiyonuyla **atlıyor** — [e2e/src/browser.ts](../../e2e/src/browser.ts): *"bypassing Steam OAuth, which cannot be scripted"*. Dolayısıyla F6 (MVP kapanışı) ve F7 gate'lerine kadar **hiçbir ekran gerçek bir oturumla, tarayıcıda görülmemişti**.

Yöntem, projenin `ForwardedHeadersNotRegistered` dersinin ölçeklenmiş hâli: **çıktıyı kullanmaya çalışmak**, kusur aramak değil. Dokuz bulgunun hiçbiri aranarak bulunmadı; hepsi ürün kullanılmaya çalışılırken düştü.

## 4. Bulgular

### 🔴 B8 — Hiçbir kullanıcı UI üzerinden işlem oluşturamıyor (kapalı döngü)

Ürünün birincil eylemi arayüzden **ulaşılamıyor**:

1. `/tr/transactions/new` → *"MA aktif olmadan işlem başlatamazsınız"*, form alanı **0**
2. Tek çıkış **"MA'yı aktifleştir"** → `/auth/mobile-authenticator`
3. O sayfanın tek eylemi "Yeniden kontrol et" ve Steam'e **hiç sormuyor**. Kendi yorumu: *"recheck just re-reads the latest verified state from /auth/me (WP11 decision)"*
4. `User.MobileAuthenticatorVerified`'ı yazan **tek** kod [SteamTradeUrlService.cs:46](../../backend/src/Modules/Skinora.Users/Application/Settings/SteamTradeUrlService.cs#L46) = U17
5. **U17'yi çağıran hiçbir frontend kodu yok** — dizge frontend'de yalnız [users.ts:50](../../frontend/src/lib/api/users.ts#L50)'deki bir **doc yorumunda** geçiyor. Ayarlar/Profil'de alan yok; kabul formundaki alan sadece ön-doldurma
6. Kabul akışı da bayrağı yazmıyor — `TransactionAcceptanceService` URL'i body'den okuyup canlı probe yapıyor, alanlara dokunmuyor

Bayrak `false` doğuyor ve arayüzde `true` yapmanın yolu yok. Kullanıcının MA'sı gerçekten açıkken bile (`{"active":true}` ölçüldü) ürün reddediyor.

**Backend yarısı sağlam** (§3.5 U17 testi) — eksik olan yalnız UI çağrısı. `WalletAddressInput` deseni ve U17 sözleşmesi hazır.

**Neden dört faz görmedi:** E2E süitleri MA'yı JWT enjeksiyonu veya doğrudan API ile geçiyor; hiçbiri *"yeni kullanıcı arayüzden nasıl uygun hâle gelir"* sorusunu sormuyor.

### 🔴 B9 — Sidecar'ın envanter istemcisi Steam tarafından reddediliyor

Aynı konteynerin içinden, aynı dakikada: `steamcommunity` paketi **429**, düz `fetch` (birebir aynı URL + `Referer` + `count=1000`) **200**. Her denemede tekrarlanıyor.

**Elenen hipotezler:** User-Agent · URL biçimi · profil gizliliği · `STEAM_API_KEY`. Geriye paketin kullandığı eski `request` yığını kalıyor. Düzeltme yönü: `getUserInventoryContents` yerine doğrudan `fetch` — sidecar `CEconItem` biçimini zaten kendisi ayrıştırıyor.

**Önemi:** envanter okunamazsa satıcı item seçemez; B8 düzeltilse bile işlem oluşturulamaz.

### 🔴 B1 — Kimliksiz bir istemci tüm platformun oturum katmanını 60 sn düşürebiliyor

- `auth` politikası **10/60 sn** ([appsettings.json:145](../../backend/src/Skinora.API/appsettings.json#L145)), `UserScopedPolicies`'te **yok** → IP bazlı
- `AuthController` **sınıf düzeyinde** `[RateLimit("auth")]`, `me` için istisna yok → `/auth/me`, `/refresh`, `/logout` aynı kovada
- Proxy arkasında IP herkes için nginx → kova **tüm platform için tek**
- Kovayı tüketen 10 istek **401** → token gerekmiyor

**Sessiz bozulma:** `/auth/me` 429 dönünce `AdminGuard` rolü çözemiyor ve süper admini dashboard'a atıyor — *"admin değilsin"* gibi. Hata mesajı yok.

**Pratik bütçe:** tam sayfa yüklemesi başına 2 `/auth/me` → platform genelinde **~5 sayfa yüklemesi/dakika**.

**İki ayrı kusur:** *yayılma yarıçapı* = forwarded headers (kayıtlı 🔴) · *kova tasarımı* = her sayfanın yaptığı okumayı giriş denemeleriyle aynı kovaya koymak (düzeltilse bile NAT arkasındaki ofisi kırar).
